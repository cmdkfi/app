## Discrepancies

1. **Historical-case dashboard claim appears stale.** Protocol README line 78 says similar historical cases are shown on the dashboard. No such feature was found in the supplied guided-flow app. Its deployed primary JavaScript matches the supplied source build.

2. **Web bundle documentation contradicts the implementation.** `../cmdk-app/README.md:156` says the production bundle contains no `"sandbox"` string. `app/scripts/bundle-markers.mjs:1` explicitly says the sandbox ships; its forbidden markers only cover test fixtures/wallet controls. The live sandbox exists and is labelled.

3. **“Never increase your debt” needs the rounding exception.** The live app, `screens/Settings.tsx:63`, `screens/Position.tsx:111`, and [landing page](https://cmdk.fi/) use the absolute claim. The protocol README permits migration rounding. The existing fork test demonstrably changes combined debt from `1162305897` to `1162305898` units—a **one-micro-USDC** increase. Economically negligible, but the absolute wording is inaccurate.

4. **The web floor wording is stronger than the protocol guarantee.** `screens/Settings.tsx:25` says “The agent never reduces below this.” The protocol README expressly permits better-than-oracle fills to undershoot the floor slightly. The UI should preserve that qualification.

5. **Sandbox copy calls simulated values live.** With the simulation banner visible, S1 still says “at the live market oracle” and “market read (block 30000000).” Observed sandbox traffic contained no RPC calls. The banner mitigates the ambiguity, but these labels should say simulated.

6. **Product-wide control claims exceed the guided UI’s controls.** The protocol supports owner-selected corridors and revocation, but the supplied UI uses fixed 50/70/30/20 settings and provides no corresponding corridor editor or revoke control. Its own README discloses fixed settings; this is a UI scope gap rather than a missing contract capability.

7. **The pinned source reproductions are incomplete in this screening.** Neither a matching pinned vault rebuild nor two matching agent-image builds was obtained. The vault attempt was stopped while compiling; the agent build failed from insufficient memory. These are verification gaps, **not evidence that reproducibility claims are false**.

8. **The complete browser suite was not validated.** The stated count of 85 is correct, but enumeration and successful unit tests do not establish that all browser scenarios pass. The recorded 0.44–0.70-second refresh and 1.8-second initial-load figures were not independently reproduced.

9. **Research numbers are supported by submitted records, not independently regenerated here.** The size-filtered CSV contains `1890/1895` and `5009/5011`; incident tables contain the claimed comparative results; the scene arithmetic checks out. I did not independently reconstruct the 20,479-liquidation dataset, replay all cases, reproduce the idealized BTC table, or rerun paid model experiments. Those remain simulations/reported research, not demonstrated live savings.

10. **Other externally sourced numbers remain unconfirmed.** This includes competitor incidents/controls, borrower and market-size figures, historical signing-network membership, infrastructure-cost estimates, and the broad comparative “tightest limits” claim. They should not receive the same evidentiary weight as verified code and receipts.

11. **No missing root Verify-it script or evidence path was found.** The notable execution obstacles were permissions, resources, an occupied browser-test port, and prohibited state-changing/signing operations—not nonexistent prescribed paths.

12. **Private web repository remains a publication question.** The supplied copy was sufficient to screen and reproduce the deployed bundle. It does not establish that judges will have public source access by the required deadline.
