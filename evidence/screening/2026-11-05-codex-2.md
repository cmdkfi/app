## Discrepancies

1. **Executor replacement does not provide the immediate per-market revocation described.**  
   README line 90 says `set_executor` revokes the old executor’s Morpho authorization and allowances for that market. The [implementation](vault/src/lib.rs:381) defers revocation until no market still references the old executor. All three deployed markets currently share one executor. This qualification matters to the advertised escape mechanism.

2. **The slice maximum cannot be lowered by an owner message in this version.**  
   README line 158 promises this. `slice_max` is set during initialization and read during reduction; no owner method updates it. `setup` and `set_corridor` arguments contain no slice-limit field.

3. **Strict floor and target-undershoot claims exceed the implemented checks.**  
   The [repayment calculation](executor/src/CorridorMath.sol:36) assumes oracle-price execution. The swap accepts better prices and performs no final floor/target rejection. Pure arithmetic using that formula gives:
   
   - Debt 40, oracle collateral value 100, floor 30%, default 20% budget, and a fill 1% above oracle: repayment approximately 14.285714 leaves **29.950577% LTV**.
   - Debt 71, value 100, protective target 50%, and the same better fill: repayment 42 leaves **49.644068% LTV**, an undershoot of **0.355932 percentage point**, exceeding README line 160’s asserted 0.1-point bound.
   
   These are code-derived counterexamples, not submitted transactions. Better execution retains more collateral and lowers LTV; the discrepancy concerns the claimed exact guarantee.

4. **The sale budget has an additional, undocumented count limit.**  
   `Executor.sol:52,583–590` stores only 16 discretionary sales per caller/collateral token and refuses overwriting a still-active entry with `SellBudget`. A seventeenth sale within 24 hours can therefore fail even with monetary budget remaining.

5. **“One exit” is per market, not a vault-wide daily limit.**  
   README line 49 says “or one exit.” `closedForAgent` is indexed by caller and market. README line 85 provides the more accurate per-market qualification. Likewise, the floor is a reduction constraint, not a prohibition on an authorized full exit.

6. **Privacy wording is internally inconsistent.**  
   README line 95 claims private reasoning; steps 8 and the roadmap correctly disclose public transcripts. The endpoint actually exposes them, including reasoning. Private funding is also a future feature, explicitly disclosed elsewhere.

7. **The scene keeper is a narrower comparator than “the same numeric screens” suggests.**  
   `scripts/scene.py:136–150` implements the protective LTV/session rule. It does not run all agent screens, including utilization and feed freshness. The agent has a separate twin mode, but the recorded scene keeper is the Python implementation. This does not invalidate the observed crash results.

8. **Research reproduction material is missing beyond the disclosed large files.**  
   [DATA_NOT_INCLUDED.md](research/liquidation-dataset/DATA_NOT_INCLUDED.md:3) says every script and small result tables are included. They are not. Missing examples include:
   
   - `research/liquidation-dataset/scripts/`, including requirements and replay programs.
   - `data/counts_market_year.csv`, `headline.csv`, `per_asset.csv`, `step2_size_headline.csv`, `calibration_grid.csv`, `selected_policy.json`, and `step4_metrics.csv`.
   - Under `research/judge-evidence/`: `scripts/retrieve.py`, `data/injections.json`, `data/manifest.json`, `runs/summary.json`, and the referenced clean/retrieval run directories.
   
   The research instructions also retain planning-repository paths. All literal paths directly required by the root README’s numbered verification steps were present.

9. **Some feature demonstrations remain unconfirmed.**  
   The available live transcripts demonstrate reduction and migration, not exit. I found code for `open_from_stables`, repay, cancel, and sweep, but did not independently demonstrate those individual paths. README line 9’s “everything else below is [demonstrated]” is therefore stronger than this screening establishes.

10. **Some comparison figures require careful interpretation.**  
    Gap and whipsaw participants start with different cash balances, explicitly noted in their evidence. Raw final net values are not directly comparable without normalization. The keeper’s cash is an accounting allocation because its wallet also funds the pool and liquidator.

11. **Submission metadata is unfinished.**  
    The README’s team/license/contact section still says “To fill before submission,” although a repository `LICENSE` file exists. The `pre-hackathon` tag exists, but its commit author timestamp is **2 November 2026**, while its description says the prototype was written 26–31 October. Commit metadata alone cannot establish the claimed development dates.

**Numbers not independently confirmed:** the historical 20-position survival/$2.65M result; keeper 3/10 and 1/10 results; broad replay savings of 1,890/1,895 and 5,009/5,011; model timing, false-exit, injection, and repeatability statistics; the idealized BTC/value examples; and production cost estimates. The printed market-year counts sum to **20,479**, but the underlying events were not independently recounted.

External market-size, competitor, incident-loss, and infrastructure assertions also remain unconfirmed by this repository/live-state screening—including the Coinbase figures, competitor adoption/security figures, Aave incident figures, Rhea/stock-market figures, and mainnet MPC operator count. The **testnet MPC threshold of 11 with 16 participants was independently confirmed** by a view call.
