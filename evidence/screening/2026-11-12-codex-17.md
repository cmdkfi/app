## Discrepancies

### Substantive reporting qualifications

1. **Historical injection results do not measure the deployed corroboration rule.**  
   The reported **21/30 raw exits → 2/30 gated exits** is supported by archived results. However, `research/judge-evidence/README.md:221,233–236` describes an older offline approximation with manually labelled semantic support, publisher identities, retractions and different freshness/action rules. Current `agent/src/logic.rs:305–365` checks critical risk and recent distinct feed IDs. Calling the historical result the effect of “the agreement rule above” overstates its applicability to production code.

2. **The incident replay’s numeric baseline is not the live deterministic twin.**  
   `incident-replay-results.md:83–88` uses utilization/withdrawability, oracle-versus-market gaps and held-token/ledger ratios. The deployed screens at `logic.rs:77–100` differ. The research documentation acknowledges this; the main README’s table label conflates them.

3. **“Passed automated checks” compresses mixed results into a stronger headline.**  
   `evidence/analysis/slither.txt:2–7` reports IR-generation failures for `reduce`, `migrate` and `ltvOf`, a coverage limitation omitted from the prose summary. Halmos proved two properties and timed out on six. Cargo-audit reported advisories; other static findings were triaged by the authors. Most qualifications are disclosed in the detailed analysis README. These results do **not** establish an exploitable flaw, but they are not an unconditional clean pass.

4. **One dependency-advisory description identifies the wrong version.**  
   `evidence/analysis/README.md:45` associates vault runtime `crypto-bigint 0.7.10` with the advisory. The actual audit log flags **0.5.5** and states **≥0.7.6 is patched**. Dependency-tree checks placed 0.5.5 in the host test chain, not normal WASM dependencies. This overstates that particular runtime exposure.

5. **The 53-minute statement is a simulation bound, not a universal historical-oracle bound.**  
   The calculation reproduced, but `research/venue-split/scripts/part_b_oracles.py:27–33` selects five stress windows and models oracle behavior. It should not be read as a guarantee about every real oracle update.

6. **The saved/observed fractions do not describe every policy outcome.**  
   The headline denominators are correct. The accompanying data also contains policy-liquidated episodes among positions that actually survived: **nine training and three holdout cases** at the $1,000 cutoff. Judges should consider both sides of that comparison.

### Wording and interface precision

7. README line 81’s “nobody … add a key” is literally too broad: `vault/src/lib.rs:498` deliberately adds an attested restricted key. The defensible claim is **no arbitrary/full-access key**. Nearby paragraphs explain this.

8. The permissions table’s “Anyone else: Nothing on your vault” omits authenticated public entry paths: anyone may relay a valid owner message, and an agent satisfying the approved attestation may register. No authorization bypass was demonstrated.

9. “Stale feed refuses new risk (open)” is incomplete shorthand: migration also checks destination freshness. Reduce and exit correctly omit that gate.

10. Web app `Settings.tsx:73` says the agent cannot send funds anywhere except repaying the loan. An allowed exit also returns collateral to the derived position address. This is copy imprecision, not an unauthorized-recipient finding.

11. The web panel’s “Running agent matches the approved version” checks served compose hashes against approval/index data; it does not independently verify a fresh quote. The panel discloses that limitation.

12. Landing source comments contain stale README line numbers. The corresponding claims still exist. The web README’s dated six-request refresh measurements were not re-established; the current performance test permits **up to eight requests** and passed.

## Preliminary score: **8.5/10**

The strongest evidence is the combination of working testnet flows, substantial NEAR integration, on-chain restrictions, exact artifact reproduction, a matching live web deployment, and broad passing tests.

This score is preliminary and is **not a recommendation to accept or reject**.
