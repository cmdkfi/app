## Discrepancies

- D1. **Agent-side sale skip not in the README.** `agent/src/logic.rs:573-582` (`sale_blocked_by_pool`) withholds every `reduce` and `exit`, protective ones included, while the pool is more than 1% below the oracle; its unit test uses a protective reduce at LTV 0.75. The README says the executor requires fills within 1% of the oracle and that "protective selling is not budget-limited", but never says the agent itself does not broadcast a protective sale in that state (the executor would revert `Slippage`). On testnet the team's rebalancer keeps the pool inside ±1%; on mainnet a crash can put a DEX pool more than 1% under Chainlink, and then protection waits (the "Worst case" paragraph half-acknowledges this: "the 1% bound is against the oracle, which can itself sit a few percent from the exchange price during a crash").
- D2. **`invalid_schema` count.** README step 8 says one; the live index has two. The README states that the counts grow with uptime, so this is a stale number, not an error.
- D3. **0.16 vs 0.14992 NEAR.** `evidence/scenes/exit-v4.md:7` says the agent waits for 0.16 NEAR; the code waits for 0.14992 (`agent/src/logic.rs:778-782`); the relayer's `/fund-agent` tops up to 0.16. Harmless.
- D4. **Stale test counts in `evidence/README.md`:** "web app 162 unit and 88 browser"; `main` now has 174 unit tests and 124 browser scenarios (109 passed + 14 skipped + 1 that passed on rerun). `cmdk-app/README.md` says 174 correctly.
- D5. **Build command wording.** README step 2 says the script runs `cargo near build reproducible-wasm` in the pinned image; the on-chain NEP-330 `build_info.build_command` reads `cargo near build non-reproducible-wasm --locked` (the inner command cargo-near records for the container run). A reader comparing the two strings could think they disagree; they do not (the outer command, image digest `ccb22bb4…` and source snapshot are recorded and the hash matches).
- D6. **Deterministic twin.** README step 10: "The deterministic keeper runs the agent's protective rule … without the model". In the scenes the keeper is `scripts/scene.py`'s Python re-implementation of the rule on the test wallet's own executor position (`scene.py:7-8`), not the agent binary's `twin` mode. - D7. **`approve_measurement` leaves an existing key.** README: "changing the code needs your approval." ## Questions for the human judges

1. Agent-side skip (D1): in a real crash where the DEX pool trades more than 1% under Chainlink, the agent withholds protective sales and the executor would refuse them. Is this acceptable for v1, and should the README state it next to "protective selling is not budget-limited"?
2. Owner/agent separation: the executor treats owner and agent as the same `msg.sender`; the vault's selector table and the NEAR function-call key are what stop the agent from calling `open` or `setCorridor`. Does the hackathon's security track want that dependency called out more explicitly than the permissions table does?
3. `approve_measurement` does not revoke the key registered under the previous measurement (D7). Should the app's "Approve current agent version" flow also send `revoke_agent`, or document the up-to-7-day overlap?
4. Independence of evidence: the text-path exit (step 10, `exit-v4`) was triggered by two feeds the team publishes, and the pool the 1% bound is measured against is kept at the oracle by the team's rebalancer. The README labels both. Does the demonstration count as showing the mechanism, or should the team be asked for a run with an external feed (e.g. Base's status RSS) as one of the two sources?
5. The model's contribution: by the README's own table the model changed nothing in the three price scenes; its value is the venue-stress `migrate`, the feed-driven exit and earlier exits in an offline replay. How much weight does the AI track give to a design whose honest claim is "the rules do the protecting, the model chooses between fixed options"?
6. The judge is non-reproducible (same request, different answers in up to a third of repeats, per the README). Transcripts are signed, but is a signed non-deterministic decision sufficient attribution for the "AI Security" track?
7. Testnet-only claims the README defers to the production release (NEAR Intents, Confidential Intents, any-chain deposits, private funding route, buy-back) are not demonstrable; the README is careful to label them. Should the privacy track score only what runs?
8. Are the automated-check outputs in `evidence/analysis/` (Slither, Aderyn, Semgrep, Medusa, Halmos, cargo-audit, clippy) something the judges want reviewed, given that no external audit exists?
