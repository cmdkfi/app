## Discrepancies

### Documentation and wording

1. **Executor replacement wording omits conditions and completion steps.** README says the vault revokes old authorization once no market uses that executor. `vault/src/lib.rs:395` includes Morpho revocation only when the owner-signed `revoke_authorization` flag is true. The provided relayer validates that flag against Base state (`scripts/relayer.py:490`). The resulting Base transactions must also land. The standard workflow supports the intended behavior; the unconditional wording is imprecise.

2. **Web setup does not skip every already-existing approval.** Its README says setup performs “only what Base does not already show.” `cmdk-app/app/src/protocol/owner/message.ts:67` deliberately sends `approve: true` for every market during repeated setup. Other setup components are selectively omitted.

3. **Landing migration copy drops the rounding qualification in prominent places.** `landing/src/content/landing.ts:144,469` says “same debt.” The implementation permits two units of rounding. The landing FAQ correctly qualifies this as up to **0.000002 USDC**, so its wording is inconsistent rather than wholly undisclosed.

4. **Landing news-input wording is ambiguous for the shipped build.** `landing/src/content/landing.ts:590` mentions “status feeds and news.” The main README limits production-agent feeds in this build to Base status and two team-authored demo feeds; broader news ingestion is future scope. The landing passage also discusses research, which makes its intended scope unclear.

5. **Landing prompt count needs qualification.** “Two transactions and three signatures” describes a typical fresh open. Existing WETH, resumed setup, and gas top-ups change the count, as the app README explains.

6. **Minor stale web documentation/comments.** The README says CI installs Chromium using `--with-deps`; current workflows explicitly install Chromium without that flag. `app/src/flow/build.ts:1` says sandbox requires `VITE_SANDBOX=1`, whereas `vite.config.ts:4` includes it by default unless disabled.

7. **Broad headlines need the detailed qualifications.** “Without selling” and “cannot move your money” are not literal descriptions of every action: the agent can sell collateral to a fixed pool, repay Morpho and exit. The README’s detailed permissions and economic-risk sections explain the narrower arbitrary-recipient restriction.

### Paths, commands and verification limits

8. **No missing command or file blocked the main Verify-it sequence.** The original checkout lacked initialized `forge-std`, but the README explicitly documents initialization; tests passed after doing that in a temporary clone.

9. **Historical research notes retain unavailable paths.** `research/judge-evidence/incident-replay-results.md:1` names private planning paths such as `incident_replay/`, `backtest_scripts/incident_replay_llm.py`, and an old `/private/tmp/...` output directory. `research/README.md` discloses this. 11. **Independent publishers are not enforced by the text gate.** Code distinguishes feed IDs. Two demo feeds have the same publisher. The main README discloses this; the demonstration does not establish independent corroboration.

12. **Agent-image rebuild and interactive browser behavior remain unverified because of environmental blockers.** Neither is evidence of a product defect, but neither can be marked passed.
