# Discrepancies

1. **Mobile functionality is materially overstated in the web README.**  
   It describes an application that remains mounted across widths, mobile layouts and mobile flow tests. Actual code unmounts the application shell below **960 px** and shows “Open cmdk on a desktop browser.” Live inspection at **390×844** confirmed this. The landing page correctly describes desktop support. See Web `app/src/components/App.tsx:157`, `DesktopGate.tsx:1`, and `e2e/shell.spec.ts:111`. [Live mobile screenshot](/private<tmp>).

2. **The web README’s light-design and mobile screenshot claims do not match this deployed branch.**  
   `app/src/main.tsx:32` explicitly selects dark theme. The visual test file uses a fixed **1280×2200** desktop viewport; it does not substantiate the claimed mobile screen comparisons. The referenced `../design-proposals/full-light-v3/` is outside the supplied checkout and unavailable here.

3. **“Sandbox never contacts a network host” is too absolute.**  
   Direct entry into a fresh sandbox produced no RPC requests and no localStorage entries. Entering sandbox from live mode produced two subsequent Base `eth_call` requests. These appear consistent with unfinished live reads, but the precise cancellation cause was not proven. No external writes occurred. [Captured requests](/private<tmp>).

4. **The browser suite was not clean on its first full run.**  
   One discovery/navigation timeout occurred; the isolated rerun passed. This should be recorded as a flaky or load-sensitive check until resolved, rather than reported as an uninterrupted 88/88 pass.

5. **One attestation document overstates operator identity.**  
   `agent/MEASUREMENT.md:43` says approving the measured `--operator cmdk` argument means approving “this code, run by this operator.” A different operator can reuse that string. It binds configuration, not independently authenticated operator identity. The main README’s statement that the vault checks measurement rather than operator is more accurate.

6. **Protocol configurability exceeds the current web UI.**  
   Owner-set corridors exist in the contracts and scripts, but the web interface uses published preset rules. “LTV you choose” should not be interpreted as a currently available arbitrary web control.

7. **Some research paths are historical rather than runnable paths in this checkout.**  
   Research documents refer to `backtest_scripts/incident_replay_llm.py`, `incident_replay/`, and historical temporary-workspace locations that are absent here. `research/README.md` explains historical locations and some missing original material, but those references still cannot be executed directly.

8. **Research totals were checked against published summaries, not independently regenerated from raw history.**  
   I confirmed the **20,479 Morpho** aggregate, **1,890/1,895** and **5,009/5,011** saved-position summary counts, and the published injection summary’s **21/30 → 2/30** filtering result. I did not rerun the full historical extraction, parameter grid or paid model experiments. The **20-position/$2.65M** sample and idealized **$5,987 versus $8,811** example therefore remain reported simulations, not independently reproduced results.

9. **Several quantitative claims remain unconfirmed in this screening.**  
   These include production per-vault costs, action costs, sustained 3–10-second agent-loop timing, the web README’s historical latency improvements, mainnet’s signer threshold, market adoption/competitor totals, third-party incident loss estimates, and venue-coverage market sizes. They should not receive the same evidential weight as the reproduced artifacts and live reads.

10. **Important limitations are disclosed, rather than hidden discrepancies.**  
    No private funding route, BTC entry, additional lending venue, buy-back or outage-independent protection is demonstrated. The testnet uses team-controlled markets/liquidity maintenance and a scripted liquidator. Transcripts are public; transcript verification trusts the agent’s recorded model-attestation verdict rather than independently revalidating the raw model quote. The README generally states these limits clearly.

No missing command or missing evidence file prevented the authorized core Verify-it checks. The literal network-writing attack command was deliberately excluded; its documented local alternative passed.

# Preliminary score: **8.0/10**

This is a screening assessment of the whole submission, not an official rubric calculation.

The strongest reasons for the score are exact vault and agent-image reproducibility, matching deployed executor source, working live state, substantial local test coverage, successful adversarial checks on a local fork, and public evidence that includes failed protection scenarios.

The main deductions are the web documentation’s concrete inaccuracies, the browser timing failure, incomplete independent reproduction of research results, and limited demonstrated incremental benefit from AI over deterministic protection. Privacy and broader cross-chain functionality remain future work. The operational dependency on NEAR, signing infrastructure, relayer and agent also remains significant, as disclosed.

**This score does not accept or reject the submission. Under Q-017, human judges decide; a low AI score alone cannot reject it.**
