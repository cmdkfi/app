## Discrepancies

### Implementation and guarantee mismatches

1. **Three methods versus four.** README line 54 says four named methods. Code and live key permissions contain three.

2. **Advertised numeric screens are broader than implemented screens.** README lines 48 and 79 name volatility, borrow rate, oracle-versus-second-price and liquidity screens. The actual screen function has four conditions: LTV above act, zero collateral value, utilization above 95%, and stale/nonpositive feeds. Borrow rate and available liquidity are computed, but that does not make them standalone alarm screens. Pool price disagreement is an execution precheck, explicitly excluded as corroboration.

3. **The model is not called only when a rule fires.** `agent/src/main.rs:59,630–650` and `logic.rs:400–408` also trigger calls for new feed items and six-hour digests, including a startup digest.

4. **“Independent sources” means different feed IDs.** Two allowlisted feeds are published by the same team. They can satisfy the two-feed rule without independent publishers. Only Base’s status RSS is an external source; the README’s wider security/news/governance coverage is not implemented as that broader source set.

5. **Retraction cancellation was not found.** New feed items can request another judgment, but the inspected code does not deterministically cancel a text-only alarm when the same source retracts it. Judgment relevance checks screen sets; text corroboration checks cited feed IDs, timestamps and risk.

6. **Step 4 incorrectly describes which LTV the policy uses.** `ltvOf` reads stored totals, but `reduce` calls `Morpho.accrueInterest` before checking the position (`Executor.sol:250`). The agent also computes accrued debt (`agent/src/chain.rs:521–530`). Therefore the matching “at lastUpdate” view is not necessarily the transaction’s policy LTV.

7. **Floor and sell-budget wording is too broad.** These constrain discretionary `reduce`; `exit` can sell collateral to repay all debt without applying that floor or budget. Exit closure is per market, so “one exit” is not a global daily limit across the vault’s markets.

8. **Protective budget exemption can continue below the act line.** `Executor.sol:258–266` maintains a session for up to 24 hours while LTV remains above target plus tolerance. The README’s statement that it needs LTV to “actually be above the act line” describes session initiation, not every subsequent protective slice.

9. **The stated 0.1-percentage-point target bound is not enforced after a favorable fill.** `TARGET_TOLERANCE` controls session continuation; there is no post-swap target/floor assertion. As a static arithmetic illustration using the implemented formula: debt 80, collateral oracle value 100, target 50% gives repayment 60. A fill 1% above oracle sells collateral worth 59.40594 at oracle, leaving LTV **49.26829%**, or **0.73171 percentage points below target**. This is a code-derived example, not a live transaction result.

10. **Migration preserves debt subject to rounding, not exact equality.** `Executor.sol:346–349` permits destination debt up to moved assets plus one loan-token unit. Strict “never increases debt” and “identical debt” wording needs this qualification.

11. **`set_executor` does less than the guarantee table suggests.** It updates one market and clears its corridor flag. Old permissions remain while another market uses the old executor; final Morpho revocation depends on an owner-signed flag. It does not set up the new executor automatically. The normal relayer checks the flag against Base, but that check is off-chain. New setup and successful broadcasting remain necessary.

12. **“Every loop” and “every block” overstate collection guarantees.** The agent polls sequentially rather than subscribing to every block. Routine ticks can return without writing a transcript; transcripts are written for decision loops (`main.rs:665–679`). Write failures are logged and do not stop operation.

13. **Several smaller wording inconsistencies remain.**
    - The demo market uses **dUSDC**, not USDC, despite the technology table calling all three WETH/USDC markets.
    - The attestation dependency is direct `dcap-qvl`; no Shade Agent attestation crate was found in the relevant manifests, locks or source.
    - Owner-signed `sweep_eth` is another outbound transfer path besides `withdraw`.
    - The introductory buy-back wording and “everything else below is [demonstrated]” conflict with later explicit deferrals and missing demonstrations.
    - Step 2 names `near.vault_code_hash` beside a hex display; that manifest field is base58. The corresponding hex field is `near.vault_code_hash_hex`.

The live NEAR cooldown of **120 seconds** and executor cooldown of **60 seconds** are distinct settings, not an unexplained failure: the agent uses the later of the two eligibility times.
