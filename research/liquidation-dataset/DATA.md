# Data files of this note

Every data file the scripts in `scripts/` read or write to recompute the numbers in `README.md`, with its size and SHA-256. Files under 5 MB are in this folder at the path shown; files of 5 MB and more are assets of the GitHub release `research-data-2026-11-06` of this repository (one asset per file; the two directories of per-case results are one `.tar.gz` each). The two files of the earlier backtest that `scripts/binance.py`, `scripts/step2_data.py` and `scripts/assemble.py` read from `../liquidation-backtest/` are listed at the end. Sizes are the files' byte counts; SHA-256 is of the file as published (for a `.tar.gz`, of the archive). The files are copies of the planning repository's, with one redaction: in `data/step4_install.log` the absolute local path in pip's upgrade notice is replaced by `research/liquidation-dataset/`.

## Download

From the repository root, with the GitHub CLI (17 assets, 1,968,184,899 bytes, 1.97 GB in total):

```sh
gh release download research-data-2026-11-06 -R cmdkfi/app -D research/liquidation-dataset/data
tar -xzf research/liquidation-dataset/data/replay_oracles.tar.gz -C research/liquidation-dataset/data
tar -xzf research/liquidation-dataset/data/holdout_results.tar.gz -C research/liquidation-dataset/data
mv research/liquidation-dataset/data/backtest_binance_1m.parquet research/liquidation-backtest/backtest_data/binance_1m.parquet
```

After this, `data/replay_oracles/` holds 4 `.npz` files and `data/holdout_results/` 13,858 `.json` files, and every path in the table exists. Check a file with `shasum -a 256 <path>` against the table.

## What stays internal, and why

- `data/raw/` (10 GB): the cache of every HTTP page and RPC response the Step 1 pull made (Morpho API, public Ethereum and Base RPCs, Binance klines). It is regenerated by the Step 1 commands in `README.md` ("Reproduction"); the scripts reuse cached pages and fetch what is missing. Only `data/raw/step1_readme_original.md`, the original data-source readme, is here. The report, validation, Step 3 and Step 4 scripts read only the derived files listed below; the Step 2 replay commands (`step2_data.py`, `replay.py`, `summarize_step2.py continuation`) also read `data/raw/market_history/`, `data/raw/morpho_positions/` and `data/raw/morpho_survivors/`, which the Step 1 pull creates (see "Environment" below).
- `data/grid_train/` (908 MB, 5,936 files): the per-policy, per-case results of the grid search on the training years. The selected policy (`data/selected_policy.json`), the calibration table (`data/calibration_grid.csv`, `data/calibration_train_results.parquet`) and the run manifest (`data/train_run_manifest.json`) are here; `replay.py train` regenerates the directory.
- `data/continuation_cache/` (77 MB, 19,794 files): per-case cache of the continuation runs; `data/continuation_results.parquet` is their summary and is here.
- `data/survivor_draws/`, `data/survivor_owner_prefetch/`, `data/history_batch_plans/` (5.7 MB together): intermediate state of the Step 1 pull (sampling draws, prefetch pages, batch plans). The selection they produced is `data/survivor_selection/` and `data/borrowers.parquet`, both here.

None of these is read when the README's tables are recomputed from the derived files; they are needed only to rerun the pull or the grid search from scratch.

## Environment

The scripts ran with Python 3.14.6 and the versions in `scripts/requirements.txt` (Steps 1–3) and `scripts/requirements_step4.txt` (Step 4, adds scikit-learn 1.9.1). The commands in `README.md` call `scripts/.venv/bin/python3`; create that environment once from this folder:

```sh
python3 -m venv scripts/.venv
scripts/.venv/bin/python3 -m pip install -r scripts/requirements.txt
scripts/.venv/bin/python3 -m pip install -r scripts/requirements_step4.txt
```

The README's Step 4 sequence installs scikit-learn from `data/raw/step4_wheels/` with `--no-index`; that wheel cache is part of the internal raw cache, so install it from PyPI with the line above instead. `scripts/replay.py` and `scripts/summarize_step2.py` read `data/raw/market_history/` (the Morpho market-history pages, part of `data/raw/`) for the borrow-rate curves, and `scripts/step2_data.py case_plan` reads the cached position pages under `data/raw/morpho_positions/` and `data/raw/morpho_survivors/`; `step2_data.py market_history` regenerates the first from the public API, the Step 1 pull the other two.

## C++ simulators

The three `.cpp` files in `scripts/` are compiled by the scripts themselves on first use, with the local C++17 toolchain; no step to run by hand:

| Source | Compiled by | Command |
|---|---|---|
| `scripts/sim_grid.cpp` | `scripts/replay.py` line 38, when `sim_grid.dylib` is missing or older than the source | `c++ -std=c++17 -O3 -dynamiclib scripts/sim_grid.cpp -o scripts/sim_grid.dylib` |
| `scripts/sim_continuation.cpp` | `scripts/summarize_step2.py` line 43, every run | `c++ -std=c++17 -O3 -dynamiclib scripts/sim_continuation.cpp -o scripts/sim_continuation.dylib` |
| `scripts/sim_diagnostics.cpp` | `scripts/loss_analysis.py` line 28, every run; the script also rewrites the source from its template before compiling | `c++ -std=c++17 -O3 -dynamiclib scripts/sim_diagnostics.cpp -o scripts/sim_diagnostics.dylib` |

The compiled `.dylib` files are not in the repository. The flags are macOS ones (`-dynamiclib`, `.dylib` suffix); on Linux the same three lines need `-shared -fPIC` and a `.so` suffix. `scripts/sim_reference.py` is the pure-Python simulator the compiled one was checked against (`data/simulator_parity.json`).
